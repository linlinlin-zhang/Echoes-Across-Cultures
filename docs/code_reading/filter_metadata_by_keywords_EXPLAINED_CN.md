# `filter_metadata_by_keywords.py` 代码说明

对应源码：[E:/Desktop/Echo/dcas/scripts/filter_metadata_by_keywords.py](E:/Desktop/Echo/dcas/scripts/filter_metadata_by_keywords.py)

## 1. 这个文件在数据链路里负责什么
这个脚本负责“基于元数据内容做规则式子集筛选”。

它通常出现在采集之后、统一化之前，适合做这些事情：

- 从一个较大的 metadata 表里抽出某类样本
- 用关键词保留某些流派、语言、主题
- 用排除词剔除明显不想要的条目
- 在需要时，把对应音频一并复制到新的子集目录

它的本质是一个“轻量但很实用的规则筛子”。

## 2. 整体执行流程
主流程在 `filter_metadata_by_keywords(...)` 中，顺序如下：

1. 读取输入 `metadata.csv`
2. 指定要检查的列
3. 对每一行的目标列提取文本值
4. 用包含关键词和排除关键词进行判断
5. 如果匹配，就保留该行
6. 校验并处理对应音频路径
7. 根据 `copy_audio` 决定是否复制音频到新目录
8. 输出新的 `metadata.csv`
9. 输出 `filter_report.json`

## 3. 辅助函数流程说明
这个文件的辅助函数刚好组成了一条很清晰的小流程：

1. `_parse_cell(...)`
   - 先把目标列中的单元格统一拆成字符串列表
   - 不管原来是普通文本、列表，还是列表的字符串表示，最终都变成可匹配文本集合
2. `_matches_keywords(...)`
   - 再拿这些文本集合去做 include / exclude 规则判断
   - 决定这一行是否保留

所以它们的关系可以直接理解成：

- `_parse_cell(...)` 负责把“列值格式问题”先抹平
- `_matches_keywords(...)` 负责在抹平后的结果上做规则筛选

## 4. 辅助函数说明
### `_parse_cell(value)`
作用：

- 把单元格解析成字符串列表

它兼容三种情况：

- 原本就是 Python `list`
- 是形如 `['a', 'b']` 的文本
- 是普通字符串

意义：

- 元数据列可能不是单值，而是列表或列表的字符串化形式
- 这个函数保证后续关键词匹配时能统一按“字符串列表”来处理

### `_matches_keywords(values, include, exclude)`
作用：

- 判断一组文本值是否满足：
  - 命中包含词
  - 且不命中排除词

规则很直接：

- 如果 `include` 为空，则默认包含条件为真
- 只要任一文本包含任一包含词，就算命中
- 只要任一文本包含任一排除词，就被排除

意义：

- 它实现的是项目里很常见的一种“高召回、弱语义”的快速筛选方式

## 5. 核心函数 `filter_metadata_by_keywords(...)`
### 4.1 参数解释
`in_csv`

- 输入 metadata 文件路径

`out_dir`

- 输出目录
- 会生成：
  - `metadata.csv`
  - 可选的 `audio/`
  - `filter_report.json`

`columns`

- 要检查哪些列
- 可以是一个，也可以是多个

`include_keywords`

- 包含关键词列表
- 至少要命中其中之一，除非这个列表为空

`exclude_keywords`

- 排除关键词列表
- 只要命中其中之一，就直接排除

`max_rows`

- 最多保留多少条
- 适合做小规模 probe 子集

`copy_audio`

- 是否把音频文件复制到新目录

### 4.2 行级处理逻辑
每条记录会经历以下步骤：

1. 遍历指定的 `columns`
2. 用 `_parse_cell(...)` 解析出这些列里的所有文本值
3. 用 `_matches_keywords(...)` 判断是否保留
4. 如果保留，再解析 `audio_path`
5. 如果 `audio_path` 是相对路径，就相对于输入 `metadata.csv` 所在目录解析
6. 如果音频文件不存在，该行会被跳过
7. 若 `copy_audio=True`，则复制音频到新的 `audio/`
8. 更新新 metadata 中的 `audio_path`

这说明这个脚本不仅做“表筛选”，还确保筛选后的子集仍然是一个可独立使用的数据子目录。

## 6. 输出报告里有哪些信息
`filter_report.json` 会记录：

- 输入路径
- 输出路径
- 检查了哪些列
- 包含词与排除词
- `max_rows`
- 最终命中的行数
- 复制了多少个音频文件
- 是否复制音频

这对回溯筛选策略很有帮助。

## 7. 这个脚本在链路中的典型使用场景
### 场景 1：从大表里抽某一类文化候选
例如：

- 先把一个来源整体导入
- 再通过国家、语言、流派关键词抽出某个文化域候选

### 场景 2：去掉明显不相关的样本
例如：

- 保留 `pop`
- 排除 `electronic`、`spoken`、`experimental`

### 场景 3：构建小规模调试子集
通过 `max_rows` 快速拿一个可跑通的小样本集

## 8. 设计优点
### 优点 1：实现简单但很灵活
不依赖复杂 NLP，仅靠规则就能解决很多前期筛选问题。

### 优点 2：兼容列表型单元格
对现实中不规范 metadata 很友好。

### 优点 3：可以把音频和 metadata 一起重建成独立子集
这比只输出一张筛选后的 CSV 更实用。

## 9. 局限与注意点
### 局限 1：关键词匹配是子串级别
容易有误召回，也容易受拼写和语言形式影响。

### 局限 2：它不理解语义
“包含某个词”不等于“真正属于某个文化或流派”。

### 局限 3：默认不处理重名音频文件冲突
复制音频时是按文件名落到新目录的，因此上游最好已经保证文件名稳定。

## 10. 面试时怎么讲
可以说：

“`filter_metadata_by_keywords.py` 是项目里一个非常实用的规则式子集抽取工具。它针对一个已有的 `metadata.csv`，在指定列里做包含词和排除词匹配，并在需要时把命中的音频连同元数据一起复制成新的独立子集。它特别适合前期粗筛、文化候选抽取和快速构建 probe 数据。”
