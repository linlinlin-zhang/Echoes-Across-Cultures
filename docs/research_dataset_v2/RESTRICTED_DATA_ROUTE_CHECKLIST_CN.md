# 闭源 / 受限数据路线清单

更新时间：2026-03-17

## 1. 目的

这份清单用于区分：

- 哪些闭源/受限数据路线适合正式论文
- 哪些只适合内部测试
- 哪些风险太高，不建议用

这里的核心不是“数据是否公开”，而是：

- **是否有明确合法使用基础**
- **是否能在论文中诚实说明来源和访问条件**
- **是否足以支撑可发表研究**

## 2. 先给总原则

### 原则 A

**“不公开” 不等于 “可以随便用”。**

即使数据不再公开分发，研究使用也仍然要看：

- 版权
- 平台条款
- 机构授权
- 合作协议

### 原则 B

对 ISMIR / TISMIR 这类论文来说，真正关键的是：

- 来源是否能说明
- 访问条件是否能说明
- 为什么不能公开是否能说明

### 原则 C

如果数据既没有明确授权，也不能稳定说明来源与访问条件，那么它更适合：

- 内部原型验证

而不适合作为：

- 正式论文主结果数据

## 3. 可发表路线：推荐

### 等级 A：正式论文可用

这些路线最稳。

满足条件：

- 有明确来源
- 有明确许可或访问授权
- 研究使用是被允许的
- 论文里可以诚实写出来源和访问条件
- 即使不能公开音频，也能写 `Data Accessibility Statement`

典型类型：

- 机构/馆藏的研究访问数据
- 学校或合作机构已有授权访问的数据
- gated dataset，但平台和作者明确允许研究访问
- 官方 OpenAPI / 研究项目访问源
- 与版权方或数据提供方书面约定的研究语料

怎么在论文里写：

- 数据来自何处
- 访问方式是什么
- 为什么不能公开
- 原始音频不再分发，但元数据、脚本、统计信息可提供

相关官方依据：

- TISMIR Editorial Policies 要求在不能公开数据时提供 `Data Accessibility Statement`
  - <https://transactions.ismir.net/about/editorialpolicies>
- ISMIR 2026 作者指南鼓励 recommendation 相关工作加入 ethics statement
  - <https://ismir2026.ismir.net/authors/author-guidelines>

### 适合我们的例子

- `COFLA` 这类可研究申请访问的数据
- `Dunya/CompMusic` 这类需要 token / API access 的文化语料
- 学校图书馆 / 档案馆授权使用的音乐馆藏
- 未来若 `tts-dataset/japanese-singing-voice` 获批访问，也可归到这一档，但要如实说明它是 gated，并说明使用限制

## 4. 条件可发表路线：谨慎使用

### 等级 B：可以作为论文补充或 exploratory 数据

满足条件：

- 能拿到数据
- 研究用途大致合理
- 但授权边界不够强，或访问方式不够优雅

这种路线可以用，但不建议当论文唯一主结果依赖。

典型类型：

- 需要进一步和数据提供方邮件确认的研究数据
- 平台允许浏览/收听，但再处理权限不够清楚
- 许可未完全公开写清，但出处正规、研究场景合理

怎么用更稳：

- 只做补充实验
- 只做敏感性分析
- 不把核心结论完全压在它上面

## 5. 仅内部测试路线：不建议进论文主结果

### 等级 C：内部原型验证可用

满足条件：

- 你个人或团队能拿到数据
- 但没有足够稳的公开授权基础
- 或平台条款和研究再处理之间存在灰区

这种路线适合：

- sanity check
- 原型验证
- 看趋势

不适合：

- 正式论文主数据
- 对外公开复现实验

典型类型：

- 个人账号下的流媒体平台“离线下载”
- 商业平台歌曲的手工收集
- 朋友分享给你的素材，但没有明确授权
- 只能“能听”，不能说明为何可研究再处理的数据

## 6. 不建议碰的路线

### 等级 D：高风险，不建议

满足条件：

- 通过绕过平台限制、抓包、第三方下载器、爬虫等方式拿数据
- 明确违反平台条款
- 无法合理说明授权基础
- 即使不公开，也明显存在版权和条款风险

这种路线不建议进入研究仓库，也不建议写入正式论文。

## 7. 平台型音乐服务的判断

### QQ 音乐 / 流媒体平台类

这类平台最容易让人误以为：

- “只要不公开就能用”

但实际上通常不稳。

腾讯音乐官方总服务协议写得比较清楚：

- 服务通常限个人、非商业用途
- 用户应按 TME 提供或批准的方式使用服务
- 未经授权不能使用插件、附加组件或第三方工具影响或使用服务

来源：

- <https://www.tencentmusic.com/en-us/protocol.html>
- <https://www.tencentmusic.com/en-us/right.html>

因此，对流媒体平台更稳的判断是：

- **内部临时 sanity check**：勉强可以考虑
- **正式论文主数据**：不建议

## 8. Fair Use 能不能兜底

不建议把它当作项目主策略。

美国版权局对 fair use 的说明很明确：

- 研究/学术可能属于 fair use 讨论范围
- 但是否成立取决于具体情境
- 对音乐这类创造性作品，fair use 通常更难简单成立

来源：

- <https://copyright.gov/fair-use/>
- <https://www.copyright.gov/help/faq/faq-fairuse.html>
- <https://www.law.cornell.edu/uscode/text/17/107>

因此：

- **fair use 不是“随便用音乐训练”的通行证**
- 更不是论文数据策略的稳妥基础

## 9. 给当前项目的最直接判断

### 可以作为正式论文路线的

- 明确 research-access 的馆藏 / 项目 / gated data
- 能写清访问条件的受限数据
- 我们现在已经做过 audit 的正规来源

### 只建议做内部测试的

- 个人从流媒体平台手工下载的歌曲
- 无法清楚说明授权基础的平台素材

### 不建议碰的

- 明显绕平台限制抓取下来的数据

## 10. 一个实用决策表

### 可以进正式论文主结果

必须满足：

- 来源正规
- 访问方式正规
- 研究使用有依据
- 论文中可说明

### 可以进补充实验

满足：

- 来源基本正规
- 研究使用大致合理
- 但授权边界没那么硬

### 只能内部验证

满足：

- 你能拿到数据
- 但不能稳妥说明研究合法性或平台授权基础

### 不建议使用

满足：

- 获取方式本身就不稳
- 明显违反平台条款

## 11. 一句话总结

**最稳的闭源/受限数据路线不是“偷偷下歌”，而是“有正规来源、有研究访问依据、能在论文里诚实说明访问限制”。**

对当前项目来说：

- **机构/馆藏/研究访问数据**：可发表
- **平台下载音频**：最多内部测试
- **绕平台限制抓取**：不建议
