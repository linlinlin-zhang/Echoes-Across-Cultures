# 受限数据使用说明

更新时间：2026-03-16  
适用范围：项目内部数据治理、合作沟通、论文附录说明。

---

## 1. 受限数据的定义

本项目中的“受限数据”指以下任一类型的音频材料：

- 需要注册、申请、审批或 gated access 才能获取的数据
- 只能在馆藏平台、机构页面或研究服务中访问的数据
- 仅允许非商业学术研究使用、但不允许再分发原始音频的数据
- 授权边界明确但不属于开源/开放下载的数据

---

## 2. 使用原则

项目对受限数据的使用遵循以下原则：

1. 仅在合法、明确、可说明的研究条件下使用。
2. 不对外分发原始音频文件。
3. 不将受限音频重新打包为公开数据集。
4. 对每个受限来源保留访问依据、来源页面和访问日期记录。
5. 对外公开时优先发布：
   - 元数据
   - 处理脚本
   - 统计信息
   - 数据集 manifest
   - 实验配置
6. 如许可或访问条款不明确，则该来源不得进入正式训练集。

---

## 3. 项目内部必须记录的内容

每个受限来源至少记录以下信息：

- `source_name`
- `source_url`
- `access_date`
- `access_mode`
  - 如：gated approval / archive access / research request / institutional access
- `license_or_terms_summary`
- `raw_audio_redistribution_allowed`
  - `yes / no / unclear`
- `notes`

若 `raw_audio_redistribution_allowed != yes`，则默认：

- 原始音频只保存在本地受控目录
- 不纳入任何公开仓库
- 对外分享时只共享非原始音频材料

---

## 4. 对模型与数据发布的影响

当数据集中包含受限音频时：

- 可以继续训练 embedding 或下游推荐模型
- 可以发布模型结果、统计表和评测代码
- 是否可以公开发布 embeddings，需要逐源检查许可

注意：

- 即使不公开原始音频，也不能默认“公开 embeddings 一定没有风险”
- 如果 embedding 可被视为受限媒体的派生表示，则也应谨慎处理并在文档中说明

---

## 5. 对论文写作的要求

使用受限音频时，论文中至少应说明：

- 数据的一部分来自受限研究访问源
- 原始音频未被公开再分发
- 已公开的内容包括哪些
- 为什么不能公开原始音频
- 读者如果想复现实验，能拿到哪些替代材料

禁止做法：

- 使用受限或版权不明音频，但不说明来源
- 故意省略访问条件，给读者造成“数据公开可得”的误导

---

## 6. 对当前项目的建议

对于 `research_dataset_v2`，建议将受限数据源视为第二阶段扩展域的合法组成部分，并采用以下策略：

- 主实验优先使用开放直取域
- 扩展实验纳入受限研究访问域
- 所有受限源统一走 access log 与 Data Accessibility Statement 流程
