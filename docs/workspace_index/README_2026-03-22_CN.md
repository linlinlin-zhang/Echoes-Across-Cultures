# 工作区版本导航与整理说明

日期：2026-03-22

这份索引的目标不是大规模挪动物理文件，而是在不破坏现有脚本路径、配置引用和实验可复跑性的前提下，把整个工作区按版本和职责重新“理顺”。

## 1. 当前建议的版本分层

### `v4`
- 这是当前主线，也是论文与最新实验应优先引用的版本。
- 核心特征：
  - 统一的 `V4` 数据契约
  - `V4 main` 作为主证据集
  - `routeA_small` 作为 sanity-check 小线
  - 双 backbone：`CultureMERT` 和 `Gemini`
  - `stage3` 训练
  - calibration-aware reranking sweep
  - `PAL-ready` 工作流

### `v3`
- 这是主线前一代，主要价值在于：
  - 三阶段训练升级历史
  - baseline comparison
  - prePAL / open benchmark 过渡资产
- 适合作为历史对照和 Appendix 补证，不适合再当最新主线。

### `v2`
- 这是更早期的数据源扩展、数据可用性审计、早期 Gemini/PAL 平台期。
- 主要保存：
  - 数据源审计
  - 非开放音乐源说明
  - 早期 Gemini embedding 和 PAL 试验
- 适合作为项目考古和数据建设背景。

### `v1`
- 这是最早期的 profile / split 资产。
- 只保留历史可追溯价值。

### `routeA` 支线
- `routeA_phase1` 到 `routeA_phase4` 是公开小线和阶段性验证线。
- 这条线很重要，但不应与 `V4 main` 混写成同等级主证据。

## 2. 顶层目录现在应该怎么理解

### 核心目录
- `configs/`
  - 所有可执行入口配置
  - 最新主线重点看 `dataset/`、`train/`、`benchmark/`、`pal/`
- `dcas/`
  - 主代码实现
  - 最新论文方法描述应以这里为准
- `storage/`
  - 数据集产物、embedding、模型 checkpoint
  - 最新主线重点看 `storage/public/research_dataset_v4/` 和 `storage/models/`
- `reports/`
  - 所有实验结果、审计结果、ablation、hparam sweep、PAL 结果
  - 最新主线重点看 `benchmarks/`、`hparam/`、`datasets/`、`audits/`
- `docs/`
  - 面向人类阅读的说明、版本报告、论文资产
  - 最新主线重点看 `research_dataset_v4/`、`manuscript/`
- `paper/`
  - ISMIR 主稿与 bib

### 支撑目录
- `scripts/`
  - 工作区外层辅助脚本
- `dcas_server/`、`web_prototype/`
  - 系统展示与原型入口，不是论文主证据链；旧 `web/` / `echo_web_publish/` 已退场

### 非主线或临时目录
- `tmp/`、`output/`
  - 临时输出
- `toy/`、`toy_small/`
  - toy 数据和小实验
- `archive/reference_sources/`、`tmp/`、`workspace_assets/`
  - 参考材料、临时缓存、人工导出都收敛到这里，不属于最新论文主线

## 5. 整理原则

- 不移动当前主线可执行配置和实验产物，避免破坏路径依赖。
- 通过“索引层”实现版本分类，而不是通过大规模物理搬家实现。
- 默认结论：
  - `v4` 是当前主线
  - `V4 main` 是当前主证据
  - `routeA_small` 是当前 sanity-check
  - `v3`、`v2`、`v1` 主要作为历史与补充证据
