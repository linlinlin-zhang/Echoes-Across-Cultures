## 优化内容

- 元数据加载后一次建立文化／来源／低质量筛选组合及规范化检索文本；缓存空间由实际曲库约束，不随未知查询字符串无限增长。元数据改变时重建索引。
- 曲库状态统计复用加载时的统计；随机种子、排序、筛选和现有返回内容保持一致。
- 推荐模型复用曲目低质量判定，更新元数据时清空该缓存。模型、嵌入、OT 相关性和排序权重未调整。
- 打包时为本地脚本、字体、图片与地图数据生成内容哈希 URL，公共资源使用一年不可变缓存；HTML 继续重新验证，修改资源后自动生成新 URL。
- 发布包增加 25 个 gzip 预压缩文件；Nginx 直接发送预压缩版本。HTML 生成时间同步更新，避免仅依赖脚本改变时误返回旧 HTML 的 304。
- HTTP/2 保持启用，访客连接保活从 30 秒增至 75 秒，并启用共享 TLS 会话缓存。私人接口、写入接口及 AI 响应没有加入公共缓存。

## 实测

| 检查 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 同进程 12 次曲库热查询，中位耗时 | 440.0 ms | 35.6 ms |
| 相同脚本的 20 访客、180 请求，总耗时 | 17.83 s | 9.24 s |
| 该批请求中位耗时 | 783.25 ms | 404.10 ms |
| 该批请求 P95 | 10182.10 ms | 3109.60 ms |
| 该批请求成功数 | 180 / 180 | 180 / 180 |

同进程查询约快 12.4 倍。前后 12 组真实曲库查询的完整返回内容一致；另检查了筛选、精确艺人优先、40 个并发读取和元数据更新失效。

浏览器缓存实测：冷访问同源传输 475,989 字节，复访 3,863 字节，命中 9 个缓存资源，减少 99.19%。对应页面等待时间为 5.17 秒与 1.56 秒。AI 调用在检查中被阻止，实际调用次数为零。

桌面与手机完整检查 23 项通过；固定种子推荐的 3 个曲目 ID 与优化前一致。已验证线上资源的哈希 URL、gzip 和不可变缓存响应头；HTML 仍为 no-cache。Nginx 配置验证通过，云端只读服务及中国主机健康正常。

这些是当前环境下的样本；网络延时、设备和并发会影响结果，不代表所有请求均能获得相同倍数。测试机存在本地 DNS 映射／网络转发层，不能据此推断巴西现场网络的长期表现。初次浏览器缓存测试使用了 Playwright 路由拦截，导致浏览器 HTTP 缓存被测试工具关闭；修正为仅在页面内阻止付费请求后，重新完成了真实缓存测量。
